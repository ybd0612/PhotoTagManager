> 版本：v0.1（初稿） · 作者：产品经理 许清楚 · 状态：待评审

## 1. 项目信息

| 项目 | 内容 |
|------|------|
| 产品名称 | PhotoTagManager（暂定） |
| 项目代号 | photo_tag_manager |
| 产品形态 | Windows 桌面应用 |
| 技术栈 | Electron + React（Vite + React + MUI + Tailwind CSS） |

| 标签体系 | 自由标签（写入图片自身的自定义 XMP `XMP-ptm:Tags`；兼容读取历史 `dc:subject`，无固定分类） |

### 原始需求复述

用户需要一款 Windows 桌面工具：选择图片根目录后扫描其中所有图片，以「仅包含图片的目录树」形式浏览（树结构与电脑一致，但隐藏空目录/无图片目录）；可对文件夹标记显示或不显示（隐藏状态需持久化）；可为每张图片编辑 XMP 自由标签并支持按标签筛选；提供图片预览（大图 + 缩略图网格 + 上一张/下一张）；要求 UI 现代化、处理大数据量目录不卡顿。

## 2. 产品定义

### 2.1 Product Goals

| # | 目标 | 说明 |
|---|------|------|
| G1 | 极速浏览 | 万级图片目录扫描与浏览不卡顿，扫描在后台进行、UI 始终可交互 |
| G2 | 精准管理 | 通过自由标签与标签筛选，让用户快速定位、整理海量图片 |
| G3 | 文件自描述 | 标签写入图片自身的 XMP 元数据，不改动图片像素；图片移动、复制或重命名后，分类信息仍随文件保留 |

### 2.2 User Stories

| # | 角色 | 故事 |
|---|------|------|
| US1 | 摄影爱好者 | 我想选择一个根目录并看到扫描进度，这样大目录扫描时我能知道何时完成、还可继续操作 |
| US2 | 摄影爱好者 | 我想以和电脑一致的目录树浏览「仅含图片」的目录，这样我能按拍摄组织快速定位图片 |
| US3 | 摄影爱好者 | 我想隐藏不需要的文件夹，这样目录树中只保留我关心的图片目录 |
| US4 | 摄影师 | 我想给图片添加/删除自由标签，这样我能用关键词组织照片且写回原文件 XMP |
| US5 | 摄影师 | 我想按标签筛选图片，这样我能快速找到所有「婚礼」「风光」等主题照片 |
| US6 | 摄影师 | 我想点击图片预览大图并前后翻看，这样我能快速确认图片内容 |
| US7 | 摄影师 | 我想查看/管理已用过的标签，这样我能统一标签命名、避免同义标签混乱 |

### 3.2 关键设计决策

| 编号 | 决策 | 说明 |
|------|------|------|
| D1 | 目录显示规则 | 目录「递归包含 ≥1 张图片」即显示。扫描时对每目录统计 `directCount`（直接图片数）与 `totalCount`（含递归），`totalCount > 0` 即显示；结果整体缓存于内存，避免展开时重复计算 |
| D2 | 隐藏规则与持久化 | 隐藏作用于目录节点，其所有子目录一并消失，且其图片不再参与父级递归汇总（R05）；取消隐藏仅恢复该目录本身。隐藏路径列表持久化到 `userData/hiddenFolders.json`，记录相对根目录的路径（根目录变化时隐藏集失效） |
| D3 | 标签存储 | 标签写入图片自身的自定义 XMP `XMP-ptm:Tags`（JSON 数组），并保留 `xmp:Label` 主标签；读取优先使用 `XMP-ptm:Tags`，兼容历史 `dc:subject`，写入时清空标准 `dc:subject` 以避免 Windows 属性面板显示旧值，同时保留 XMP 其他字段。exiftool-vendored 为子进程调用，批量操作需排队/限流 |
| D4 | 性能策略 | ① 扫描在 Worker 线程执行，主线程只接收增量结果（批推送，如每 200 文件推送一次）② 缩略图生成走独立队列 + 磁盘缓存，不重复生成 ③ 缩略图网格虚拟滚动，只渲染可视区域 ④ 目录树懒加载展开 |

|------|------|

**核心交互流程：**

1. 启动 → 空状态页，提示「选择根目录」
2. 选择目录 → 后台扫描，状态栏显示进度，目录树随结果逐步填充
3. 点击树节点 → 右侧加载该目录图片缩略图
4. 右键目录 → 隐藏（该目录及子树从树中消失，状态持久化）；「取消隐藏」恢复
5. 点击缩略图 → 预览大图，可打标签、翻页
6. 在标签筛选条选择标签 → 网格只显示匹配图片

### 3.4 Open Questions（待确认）

| # | 问题 | 默认建议 |
|---|------|----------|
| Q1 | 目录树「含图片」判定：仅直接含图片，还是递归含图片即显示？ | 递归含 ≥1 张即显示（D1），实现简单且符合直觉 |
| Q2 | 隐藏文件夹持久化范围：绝对路径还是相对根目录路径？ | 相对路径，根目录变化时隐藏集失效（D2） |
| Q3 | 标签写回时机：立即写回还是手动保存？ | 立即写回（增删即生效），失败时提示重试 |
| Q4 | 多标签筛选逻辑：AND 还是 OR？ | 默认 AND（更精确），UI 提供切换开关 |
| Q5 | 标签重命名/合并（P1）是否纳入首版范围？ | 纳入 P1，不做进 MVP |
| Q6 | 是否需要数据库缓存扫描结果以加速二次启动？ | 首版不做；图片分类信息不落独立数据库，扫描结果和标签按需读取并在内存中使用。后续若引入缓存，只能作为可重建的性能缓存，不能成为图片标签的权威数据源 |
| Q7 | RAW 缩略图依赖 exiftool 抽取，性能是否可接受？ | 用缓存 + 懒加载缓解；大 RAW 目录需实测验证 |
| Q8 | 隐藏目录是否影响标签统计（图片仍计入全局标签计数）？ | 不受影响——仅指标签管理面板的全局计数；标签筛选条的「当前上下文」计数按可见目录汇总，隐藏子树不计（R05） |

### 5.2 新增用户故事

- **US8** 作为浏览照片的人，我在预览大图时点一下「抠图」，等十几秒就能在棋盘格底上按住对比看边缘，满意才点保存——我不想为了去个背景打开别的软件再导回来。
- **US9** 作为在意隐私的人，我要求照片内容全程不出本机；模型是唯一需要下载的东西，下载前会告诉我要占多少、大概多久。
- **US10** 作为整理党，我保存下来的抠图自动带上原图标签和 `AI人像抠图`，可以一键筛出所有 AI 产物单独清理，原图不会被改。

### 5.3 已知边界（M1）

- 只有「人像抠图」一个行为。U²-Netp 是人像 matting 模型，非人像**允许选错主体**（不崩溃、不承诺"去除任意背景"）；通用抠图待 DirectML 兼容模型实测（Q14）。
- 掩码在 320×320 上计算，分屏看右图必然偏软，界面必须注明。
- 不做任何不可逆操作：没有"替换原图"，"丢弃"这个动作也不存在（不保存就是丢弃）。
