# 抠图参数面板（详情页折叠区）方案

> 建档 2026-09-29。触发点：用户提出"详情页有个折叠，打开后是功能（比如抠图），抠图能配参数，改了就能看出效果"。
> 本文只定**功能形态、边界与验收**；代码级接缝放在文末附录，不影响正文结论。
> 关联：`ai-photo-processing.md`（D12/D15/D16/D17/D18）、`../models/u2netp.md`、`../models/modnet.md`。

---

## 1. 一句话结论

**做。** 但"改了就能看出效果"这句话现在做不到跟手——必须先补一个**掩码级缓存**。所以本方案的第一件事不是画面板，是把"一次推理的结果"和"一张成品图"拆成两层，让参数只在轻的那一层重算。

## 2. 为什么现在做不到（这是前提，不是细节）

预览暂存缓存的是**成品图**，缓存键里含后处理参数。这意味着**只要参数变一个字节，整条链就全部重来**：解码 → 转正 → 缩放 → 归一化 → 推理 → 合成 → 写盘。推理本身在本机是 120～250 ms，加上前后段与落盘，一次点击就是半秒级——做成滑杆会卡成幻灯片，做成按钮也白白重算 GPU。

**关键洞察**：用户想调的"抠图强度"，绝大多数**根本不需要重新推理**。掩码已经算出来了，边缘收不放、底色换什么，都只是拿掩码再合成一次。所以：

```
一张照片
  │
  ├─ 解码 / EXIF 转正 / 缩放 / 归一化      ┐
  ├─ 推理（u2netp 320² 或 MODNet 512²）    ┘ 重：只在换模型、换质量档时跑
  │        ↓
  │   【掩码】← 本方案新增的这一层缓存      ★ 分界线
  │        ↓
  ├─ 边缘（阈值 / 羽化 / 收缩）             ┐
  ├─ 去色边                                │ 轻：拿现成掩码重算，可跟手
  ├─ 底色（透明 / 白 / 蓝 / 红）            │
  └─ 合成 + 写 alpha PNG → 预览暂存         ┘
```

分界线以上 = **重**，点了才跑，要给进度、要标代价（换 MODNet 首次还要下 24.7 MB）。
分界线以下 = **轻**，可以边调边看。

**这条线是本方案的主轴**：以后任何一个新参数要进面板，先回答"它在分界线哪一侧"，交互形态（实时滑杆 / 松手才算 / 按钮 + 代价提示）由这个答案决定，不用逐个吵。

## 3. 面板放哪，为什么只能是这里

| 候选位置 | 判定 | 依据 |
|---|---|---|
| **详情页右侧浮层抽屉** | ✅ **采用** | 不改变照片尺寸，参数与画面同屏，"改了就能看出"成立 |
| 底栏向上展开 | ❌ | 底栏刚从 146 px 收到 103 px，用户明确判过"两段各占一行白吃行高、把照片压小"是错的 |
| 设置页 | ❌ | 设置页 AI 分区有一条断言要求**零输入控件**（当初 CPU 开关刻意不放设置页就是躲它）。而且**参数天生属于"我正在处理这张图"的现场，不属于全局偏好** |
| 模态对话框 | ❌ | 挡住图，效果看不见，等于白做 |

面板三条硬要求：

1. **默认收起**，展开不遮挡人脸；图比面板窄时自动让位（或面板可拖）。
2. **键盘可达**：Tab 得到、`Esc` 关得掉，不能只做鼠标悬停展开（D17 动作必须可点可达）。
3. **始终标明"这是预览，还没保存"**——保存才写盘，这是派生文件规则的延伸。

## 4. 第一版只放一个参数：底色

| 参数 | 形态 | 分界线 | 为什么是它 |
|---|---|---|---|
| **底色** | 色板四选：透明 / 白 / 蓝 / 红 | 轻 | 最便宜、最直观、零算法风险；证件照场景是刚需；一眼看得见的变化 |

**第一版明确不放的**（不是没想到，是故意挡在门外）：

- **边缘三档（柔和/标准/收紧）** → 切片二。它要自己写阈值化、羽化、形态学，且必须逐个验证"真的影响输出"。
- **去色边** → 切片二一起。它正好治 u2netp 那圈蓝色描边，值得做，但要写像素算法，不混进第一版。
- **质量档（输入分辨率）** → 切片三以后。它在分界线**重**的那一侧，代价不好向普通用户解释，收益不如前几项直观。
- **rembg 那套 alpha matting 参数（前景/后台阈值、erode size）** → 不做。rembg 的实现是 Python + pymatting/OpenCV，onnxruntime-node 这边没有现成等价物；照抄参数形状等于给用户摆一排调了没反应的滑杆。
- **把 `CutoutParams` 现有 8 个字段全摆出来** → 不做。那是命令行参数的形状，不是给拍照者看的。

**产品定位这条要守住**：这是"本机图片管理工具"，用户是拍照的人，不是修图师。面板一旦变成"什么都在这儿调"，详情页就从"看一眼照片"变成半个工作台，与定位相反。**按动作分组，不按参数分组。**

## 5. 交互流

1. 点「抠图」→ 出结果，**掩码同时留下**（这一步是本方案新增的能力）。
2. 展开面板 → 选底色 → 画面**当场变**，不重新推理。
3. **按住图片 / 空格看原图**这套对比机制原样保留（D15），它天然就是"改前 vs 改后"的对照。
4. 换模型（u2netp / MODNet）搬进面板的**重参数区**，点了才重跑，旁边标代价；未下载的模型标体积。
5. 「保存」才写 `原名.cutout.png`。

## 6. 四条已裁定（本轮定死，实现时不必再问）

| # | 问题 | 裁定 |
|---|---|---|
| 1 | 改参数后再保存 | **覆盖** `原名.cutout.png` + 一句提示。派生文件本来就是"当前结果"，另存会堆垃圾。**落地判据（2026-10-02 定）**：只有当同名文件身上带着本次的行为标签（即我们自己上一轮导出的那张）才覆盖；没有该标签、或标签读不出来，一律退回 §4.4 的序号递增。这样裁定 1 与 §4.4「同名不覆盖」不再互相打脸——它挡的是我们不认识的东西 |
| 2 | 参数是否跨重启记住 | **会话内记住，重启回默认**。与后端选择的既有口径一致（不持久化） |
| 3 | 掩码缓存的生命周期 | 跟着预览暂存的 LRU 一起管，**不另设一套清理**；仍在 `ai-preview/` 目录内（§5.0 红线：清理只允许作用于暂存目录） |
| 4 | 面板承载"很多功能" | 第一版**只承载抠图的参数**，不做功能总入口。等切片二验证过再谈扩容 |

## 7. 性能判据（必须实测，不许拍脑袋）

"跟手"不是设计出来的，是量出来的。要量的数：

- **拖动一次到画面变化多少毫秒**。目标 ≤ 16 ms（一帧）才算得上实时；**超过就改成"松手才算"，并在文案上老实说明**，不许假装跟手。
- 技巧上应当是：预览阶段用**降采样合成**（如宽 1024）出图，松手或保存时才算全尺寸；阈值/羽化在**掩码原生分辨率**（320²/512²）上算，绝不在全尺寸上算。
- 掩码缓存命中与否要能证明：用**推理调用次数**当读数，而不是靠"感觉变快了"。

⚠️ 引用任何耗时数字必须带口径：本机是开发机（RTX 5060 Laptop + 610M 核显），且 **DirectML 到底选哪块卡从未验证**（`gpu-self-probe.md` 的 P1 未结）。所以这些数只能当同批内的相对量级，不能写进产品承诺。

## 8. 验收标准

| # | 判据 | 怎么验 |
|---|---|---|
| 1 | 改底色后**不再触发推理** | 集成测试里数 runner 的 `infer` 调用次数：第一次为 1，改参数后仍为 1。**这条必须能失败**——把掩码缓存删掉它就该变红 |
| 2 | 底色**真的改变输出像素** | 同一张图，透明底 vs 白底，成品 PNG 的角落像素值不同。不许只断言 store 里参数变了 |
| 3 | 参数变化后**不会拿到旧结果** | 成品缓存键含参数（既有预留），改参数 → 新键 → 新图 |
| 4 | 面板键盘可达、`Esc` 可关 | 组件测试 |
| 5 | 照片尺寸不被吃 | 展开面板前后，大图区高度不变（浮层不占布局） |
| 6 | 派生文件规则不破 | 未点保存时，照片目录字节数不变（沿用既有端到端断言） |
| 7 | 设置页零输入控件这条断言**未被削弱** | 该测试文件不许改；改了要单独说明理由 |

## 附录 A：代码级接缝（实现参考，不改上文结论）

- **分界线的落点**：`electron/ai/aiService.ts` 的 `execute()` 里，掩码在 `cropMaskPlane(...)` 之后、`composeCutoutPng(...)` 之前成形——**就在这一步之间把掩码落盘缓存**。
- **两级键**：掩码键 = 现有五元组**去掉** `postprocessParams`；成品键 = 现有五元组不动（`electron/ai/cacheKey.ts` 已把参数放进去了，无需改结构）。掩码是小对象（512² 单波段 float32 ≈ 1 MB），存 `ai-preview/` 内，与成品同一套 LRU 索引管理。
- **参数流转**：`DEFAULT_CUTOUT_PARAMS` 目前在 `execute()` 里写死（`toCacheParams(DEFAULT_CUTOUT_PARAMS)`），要改成从 `RunRequest` 带进来；渲染层 → IPC → 主进程这条链的载荷形状要同步加字段。
- **`postprocess.ts` 的 `toAlphaBytes` 现在是 `void params;`（恒等映射）**——底色不进这条恒等路径，它属于合成阶段（`composeCutoutPng`），别去改 alpha 计算。
- **不许动的东西**：`aiSettings.test.tsx` 的零 `input` 断言；`capabilityCatalog.ts` 里"具体形状只允许出现在清单"这条（面板不得写死 320/512）；D12「绝不自动回落 CPU」；成品 PNG 的 ICC 保留（`keepIccProfile()`）。
