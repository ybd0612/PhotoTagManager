# 模型许可准入与逐模型调研规范

> 建档 2026-09-29。触发点两条：① `v0.1.5` 已发布、GitHub 仓库公开，软件**此刻正在引导用户下载模型**，许可不再是"以后再说"的事；② 用户提出"我声明本软件仅供学习研究使用，是不是就避免了法律风险"——**答案是不能，详见 §2 第一条**，所以要把规则定在真正起作用的地方。
>
> 本文管三件事：**哪些模型可以进清单、要交出哪些证据、程序里怎么体现**。它配合 `image-model-capability-map.md` §8 的四步流程使用（本文在其中插入一步），不替代 §4.3 那条"只有实测跑通才能进 UI"。

---

## 1. 一句话结论

**许可风险落在"分发行为"，不落在"用户拿软件做出什么图"。** 所以要管的是**我们从哪里拿到权重、凭什么再分发**，而不是在界面上加一句免责声明。

---

## 2. 三条基本裁定

### 裁定一：「本软件仅供学习研究使用」**不能免除分发风险**

理由三层，任一层单独成立这句话就无效：

1. **限制不由我们的声明解除。** 能解除"不得商用/不得再分发"的只有两种：**权利人授权**，或符合法律规定的例外。后者通常覆盖**使用者本人学习使用**，一般**不覆盖**"向不特定公众分发他人训练出的权重副本"这一动作。
2. **对本项目当前的对象根本用不上。** u2netp 是 **Apache-2.0**，本来就允许商用与再分发（见 `image-model-capability-map.md` §8 已查链条）。给它戴"学习研究"的帽子，是解决一个不存在的问题，还会**误导用户**以为不能商用。
3. **它可能与事实自相矛盾。** 本项目公开发布、作者运营个人接单站、软件作为作品对外呈现。若实际带有商业性质，这句声明就成了**我们自己不会遵守的条款**——不但不护身，还伤可信度。

**它的正当用途只有一个**：**告知**——"本软件会下载这些第三方模型，各自许可如下，请你自己遵守"。约束对象是**用户行为**，不是**我们的分发责任**。

**只有一种情况它才有对应目标**：引入带**非商用（NC）**条款的模型时。但那时限制来自上游，且声明必须与"软件本身非营利"一致。**正确策略是从一开始就不引入 NC 模型**，而不是指望声明兜底。

### 裁定二：代码许可 ≠ 权重许可

常见做法是代码一个许可、权重另一套。**只看仓库根目录 LICENSE 会得出错误结论**，必须看模型卡/权重自身的声明。权重托管在仓库外（网盘、对象存储）时，仓库根的 LICENSE 是否延伸到它，存在解释空间——遇到这种就按"证据不足"处理，不按"应该可以"处理。

### 裁定三：转导出的 ONNX 必须披露来源差异

Apache-2.0 要求再分发时保留版权与许可声明、**并注明修改**。我们的权重几乎都来自第三方转导出（ONNX 版），**"这是转导出的、非上游作者一手发布"属于必须写进 NOTICE 的内容**，不是可选说明。

## 3. 准入规则（三档）

| 档 | 条件 | 处置 |
|----|------|------|
| **可用** | 一手来源或**我们自己从一手权重转导出**；许可为宽松类（MIT / Apache-2.0 / BSD）；LICENSE 文件**真实存在于仓库内** | 可进清单、可进安装包、可引导下载。附声明与归属。 |
| **需评估** | 许可为宽松但**来源链缺环**（二手镜像、无转换记录）；或权重在仓库外托管 | 可以留在清单里，但必须挂 `provenanceStatus` 标记 + 一条整改待办。**不得新增此档条目**（见 §6）。 |
| **不列** | **非商用 / 仅研究用途**；条款不明；根本没有 LICENSE 文件；或上游明确禁止再分发 | **不进清单、不进界面、不进安装包**，也不做"引导用户去下载"。与"超分源不可信就不承诺"同一处理。 |

⚠️ 判定"有没有 LICENSE 文件"要看**文件清单**，不能只看元数据自称。本项目已经吃过这个教训：`BritishWerewolf/U-2-Netp` 元数据自称 `apache-2.0`，`siblings` 里**没有 LICENSE 文件**。

## 4. 一条模型算"查过"，必须交出这些证据

缺任何一项就记为**未查**，不许写"已核实"：

```
1. SPDX 许可标识                     例：Apache-2.0
2. LICENSE 文件是否真实在仓库内        是 / 否（查文件清单，不看 README）
3. 一手 or 二手                       一手=权利人发布；二手=第三方转导出
4. 转换记录 / 可复现性                 能否从上游权重复现出同一份文件
5. sha256 + 体积                      双源都要查（hf-mirror 与 ModelScope）
6. 本机 DirectML 跑通记录              真图、耗时、显存与内存增量
7. 归属材料                           原作者、论文、上游仓库链接
```

第 5、6 项沿用既有口径（**双源查 `?blobs=true` 的真实体积**，防 LFS 空壳；**逐个实测**，防"文件能下 ≠ 功能可用"）。

## 5. 程序里怎么体现（五处）

| # | 落点 | 内容 | 状态 |
|---|------|------|------|
| 1 | 仓库根 `LICENSE` | **本项目自己的 MIT 全文**。当前 `package.json:7` 写 `license: "MIT"` 但**仓库里没有 LICENSE 文件**——正是我们批评二手镜像的那个缺陷 | ❌ 未做，成本最低 |
| 2 | `LICENSES/third-party/` + `NOTICE` | 每个模型的许可全文 + 归属，并写明"系第三方转导出，非上游一手发布" | ❌ 未做 |
| 3 | 设置或"关于"页「第三方模型与许可」只读清单 | 模型名 / 许可 / 上游来源 / 用途 / 归属 | ❌ 未做 |
| 4 | 模型下载确认文案 | 一句许可摘要，如"该模型以 Apache-2.0 提供，版权归原作者" | ❌ 未做 |
| 5 | **断言** | 清单里每条模型必须有非空 `license` 与 `provenance`，缺则**测试失败** | ❌ 未做，但最该先做 |

**第 5 项是关键**。本项目的经验已经证明机制比提醒有效：那条"AI 设置分区零 `input`"的断言之所以真挡住东西，是因为**它会失败**。靠文档提醒会漂移，靠断言不会。

**数据源必须单一**：许可与来源信息只写在 `electron/ai/capabilityCatalog.ts` 的条目字段里，界面清单和 NOTICE 都从同一处读。**不在两处维护同一事实**（与项目已定的"跨组件复用的句子进一处"同口径）。

## 6. 存量条目怎么办（u2netp 的显式处理）

规则若不能解释现实就是空规则，所以这里写死：

- **u2netp 现状**：许可类型 Apache-2.0（一手仓库确有 LICENSE 文件），但**本软件下载的是一份来源链缺环的二手转导出**（无 LICENSE 文件、无转换记录）。按 §3 属**「需评估」**。
- **处置**：**允许继续留在清单**（它已发布、能跑、许可类型无问题），但必须：
  1. 在该条目上挂 `provenanceStatus: 'second-hand'`；
  2. 第 5 项的断言对**该值给出显式豁免并写明原因**——豁免要**点名到这一条**，不得写成"允许所有条目为空"，否则就造出了一个永不失败的假断言；
  3. 登记一条整改待办：**自己从 `xuebinqin/U-2-Net` 的 `u2netp.pth` 转导出 ONNX**，换掉一手来源。
- **新增条目不享受此豁免**：从今往后新加的模型，`provenance` 必须是一手或自转导出，否则按 §3 判「不列」。

## 7. 流程接入：四步流程中间插一步

`image-model-capability-map.md` §8 已改为（**编号不重排**，避免别处"见 §8 第 3 步"的引用失效）：

```
1 定价值 → 2 验存在 → 【2.5 验许可（本文 §3 + §4）】→ 3 验能跑 → 4 进清单
```

**2.5 不过，3 就不用做**——省得花几分钟下载一个最终因许可出局的模型。

进清单时（第 4 步）除现有的 §4.3 表与 `capabilityCatalog` 外，同步追加两件事：写进 `NOTICE`、确认 NOTICE 与界面清单能显示这一条。

## 9. 许可之外的两条边界

1. **生物特征**：人脸检测、人脸修复处理的是人脸信息，那不归模型许可管，归个人信息保护类法规管。本项目的"纯本地推理、图像不出机器"（K1/K5）是显著有利因素，但仍应在隐私说明里**主动写明人脸数据的处理方式**。⚠️ 一旦允许配置代理（U7），"不上传照片内容"这句仍成立，但**绝不能**写成"不走网络、不经过任何第三方"。
2. **这不是法律意见**。本文是工程与来源核查层面的规则；§6 那个解释空间、以及"能否引导用户下载 NC 模型"这类问题，无法靠我们自己消除。要绝对稳妥需找知识产权法务确认。

```markdown
### <repoId>/<filePath>
- 用途 / 里程碑：
- 查的日期与方式：            （API/页面 URL，须可复现）
- 1 SPDX 许可：
- 2 LICENSE 文件在仓库内？：   是/否 —— 依据：<文件清单原文>
- 3 一手 or 二手：
- 4 转换记录 / 可复现：
- 5 sha256：               体积：            hf-mirror：  ModelScope：
- 6 本机 DirectML：        加载 ms / 推理 ms / 显存 Δ / 内存 Δ（CPU 须限线程）
- 7 归属：                 原作者 / 论文 / 上游仓库
- 判定：可用 / 需评估 / 不列   依据条款：本文 §3 第 __ 档
- 待办：
```

**填写纪律**：每项都要能指出出处（API 返回、文件清单、页面原文）。写"应该是""看着像"就等于没查。凡"本机跑通"必须引用**当天实测**数字，不得沿用他机的值——**K3/K8 的数字都是开发机值**。
