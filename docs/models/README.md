# 模型台账（Models）

> 建档 2026-09-29。**每个已确认或候选的模型一份卷宗**，一份一个文件，逐份过。
> 这里回答的是"**这个模型我们凭什么用、查过哪些、实测数字是什么、边界在哪**"，不是选型池（选型池在 `../design/image-model-capability-map.md`）。

## 与运行时清单的分工（避免两个事实源）

| 事实类型 | 唯一权威源 | 本台账的角色 |
|---------|-----------|-------------|
| **运行时数据**：`repoId` / `filePath` / `sizeBytes` / `sha256` / 输入张量名与形状 / 归一化参数 | `electron/ai/capabilityCatalog.ts` | **只引用，不重复抄数值**。改数值改代码那边 |
| **决策与证据**：许可结论、来源链、实测记录、能力边界、为什么入选或出局 | **本目录** | 权威源 |

**为什么必须这样切**：同一事实写在两处就会漂移。本项目已有先例（`strings.ts` 那条"抄两份已漂移"的口径）。卷宗里凡引运行时数值，一律写明"取自 `capabilityCatalog.ts`，未在此复核"。

## 卷宗模板 v1（2026-09-29 定，新卷宗一律照此写）

定这个模板的直接原因：u2netp 那份建得很扎实，但它是**手写出来的**，不是**按模板填出来的**——第二份卷宗（MODNet）一旦格式不同，事后就没法横向比，也会各自漏掉不同的项。**章节顺序固定，编号不许改**；某节确实没有内容时写"无"或"未验"，**不许整节删掉**（删掉就分不清是"没有"还是"忘了"）。

| # | 小节 | 必须写什么 | 容易漏的那一项 |
|---|------|-----------|---------------|
| 头 | 字段表 + 引用声明 | 能力/族、里程碑、状态与**许可档位**、面向用户的说法；并声明"运行时数值取自 `capabilityCatalog.ts`，本文件未在此复核" | 面向用户的说法——它决定文案能不能说过头 |
| 1 | 身份与来源 | 仓库坐标与文件路径、**两个源各自的状态（200/404）与 URL**、体积、sha256、**双源字节比对结果**、输入张量名与形状、**输出形态（几通道、是显著图还是连续 alpha）**、归一化参数 | 输出形态。它比参数量更能决定画质档位 |
| 2 | 许可 | 规范 §4 那七项证据逐条 + §3.1.1 那四件留存 + §6.1 四行已知限制 + **判定档位** | 一手仓有没有权重（≠ 一手仓有没有 LICENSE） |
| 3 | 能力边界 | 这个模型**只**适合什么、明确**不许**对用户承诺什么、已知会选错对象的场景 | 把"能跑通"写成"通用" |
| 4 | 实测数字 | 表：日期 / 后端 / 加载 / 推理 / 显存Δ / 内存Δ。**每行带日期**，同一模型复测就并列不覆盖 | 口径警告：显存是整卡已用还是本进程；开发机数字不得当产品承诺 |
| 5 | 真图验收 | 用了哪张图、与谁做 A/B、**复刻管线与生产的一致性校验值**、肉眼结论、**未验项清单** | 忠实性校验。没有它，A/B 差异可能出自脚本而不是模型 |
| 6 | 管线与产物 | 该模型在生产管线里的专属注意事项（补边、resize 核、sigmoid 判定、ICC/EXIF） | 与通用代码路径重复抄写——那些归代码 |
| 7 | 待办 | 明确列出未做与阻塞项 | 把待办写成"以后再说" |
| 8 | 变更史 | 按日期追加，**只加不改** | 覆盖旧条目会让结论失去可追溯性 |

**三条硬规矩**（模板本身管不了、必须靠人守的）：

1. **数字必须带日期与来源**。写"25 ms"没有意义，写"2026-09-29 本机 DirectML 25 ms（开发机）"才有。凡跨机引用一律标"开发机值，非产品门槛"。
2. **未验证就写"未验"**。特别是主观画质——本项目已经吃过一次"参照图被当成已知正确"的亏（见 `u2netp.md` §6）。
3. **运行时数值只在 `capabilityCatalog.ts` 陈述一次**，卷宗引用；反之，决策与证据只在本台账陈述，代码注释里不重复论证。

## 过这些条目时的规矩

1. **一份一份过，一次只动一份**——不要"顺手把下一条也填了"，那是口径漂移的来源。
2. 建卷宗先套上面的**模板 v1**，许可证据用 `../design/model-licensing-and-survey.md` §10 的七项 + §3.1.1 的四件留存，缺一项就写"缺"，**不许凭印象补**。
3. 许可按 §3.0 **白名单**判：`MIT / Apache-2.0 / BSD-2 / BSD-3 / ISC` 之外一律 ⚠ 已排除，不进入讨论。**2026-09-29 改判**：标识在白名单内、但仓库里找不到 LICENSE 文件本体的，按「可用（附披露）」处理，前提是补齐 §3.1.1 那四件（含把上游许可全文留存进 `LICENSES/third-party/`）。
4. 凡是"能不能跑"的结论，必须来自**本机真图实测**（§4.3 老规则）。文档里看着可用不算数——`Real-ESRGAN` 那个 0 字节 LFS 指针、`BiRefNet` 加载成功却执行崩，都是这条的来历。
5. 每条 ★ 之外的补漏族（I 文档结构化、L RAW 域等）**默认不建卷宗**，除非你点名。
