# 模型台账（Models）

> 建档 2026-09-29。**每个已确认或候选的模型一份卷宗**，一份一个文件，逐份过。
> 这里回答的是"**这个模型我们凭什么用、查过哪些、实测数字是什么、边界在哪**"，不是选型池（选型池在 `../design/image-model-capability-map.md`）。

## 与运行时清单的分工（避免两个事实源）

| 事实类型 | 唯一权威源 | 本台账的角色 |
|---------|-----------|-------------|
| **运行时数据**：`repoId` / `filePath` / `sizeBytes` / `sha256` / 输入张量名与形状 / 归一化参数 | `electron/ai/capabilityCatalog.ts` | **只引用，不重复抄数值**。改数值改代码那边 |
| **决策与证据**：许可结论、来源链、实测记录、能力边界、为什么入选或出局 | **本目录** | 权威源 |

**为什么必须这样切**：同一事实写在两处就会漂移。本项目已有先例（`strings.ts` 那条"抄两份已漂移"的口径）。卷宗里凡引运行时数值，一律写明"取自 `capabilityCatalog.ts`，未在此复核"。

## 过这些条目时的规矩

1. **一份一份过，一次只动一份**——不要"顺手把下一条也填了"，那是口径漂移的来源。
2. 建卷宗就用 `../design/model-licensing-and-survey.md` §10 的模板，七项证据缺一项就写"缺"，**不许凭印象补**。
3. 许可按 §3.0 **白名单**判：`MIT / Apache-2.0 / BSD-2 / BSD-3 / ISC` 之外一律 ⚠ 已排除，不进入讨论。
4. 凡是"能不能跑"的结论，必须来自**本机真图实测**（§4.3 老规则）。文档里看着可用不算数——`Real-ESRGAN` 那个 0 字节 LFS 指针、`BiRefNet` 加载成功却执行崩，都是这条的来历。
5. 每条 ★ 之外的补漏族（I 文档结构化、L RAW 域等）**默认不建卷宗**，除非你点名。
